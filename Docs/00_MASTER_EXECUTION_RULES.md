# PayMeter Master Execution Rules

## 1. 목적

PayMeter를 구현하면서 계산 오차, 상태 해석 차이, 저장 포맷 파편화, UI 중심 임시 구현이 누적되는 것을 방지한다.

PayMeter에서 가장 중요한 것은 애니메이션이 아니라 계산의 재현성이다.

## 2. 구현 원칙

### 2.1 Domain First

급여 계산, 시간 판정, 기간 누적은 UI 코드와 분리된 순수 도메인 로직으로 구현한다.

UI는 도메인 엔진이 계산한 Snapshot을 표시한다.

### 2.2 No Tick Accumulation

다음 방식은 금지한다.

```
money = money + ratePerTick
```

다음 개념을 사용한다.

```
earned = integrate(payable time segments, pay rules)
```

렌더링 속도는 표시 품질에만 영향을 주고 계산 금액에는 영향을 주지 않아야 한다.

### 2.3 Explicit Time State

현재 시각만으로 모든 것을 추정하지 않는다.

정규 근무 이후에는 최소한 다음 상태를 구분한다.

- 정규 근무 종료
- 무급 초과시간
- 유급 초과근무
- 사용자가 퇴근 처리한 상태

### 2.4 User Controlled Pay Policy

앱은 특정 국가의 법정 수당을 자동 확정하지 않는다.

사용자가 다음 중 필요한 방식을 지정한다.

- 기본 시급 배율
- 별도 초과근무 시급
- 고정 추가수당
- 배율 또는 시급 + 고정수당

향후 국가별 템플릿을 제공할 수 있으나 템플릿은 계산 편의 기능으로 취급한다.

### 2.5 Local First

V1 기준:

- 핵심 설정은 localStorage
- 기간 이력, 근무 이벤트, 일별 Override는 IndexedDB
- 네트워크가 없어도 핵심 기능 동작
- 서버 인증 없음
- 계정 없음

### 2.6 Data Versioning

저장 데이터에는 반드시 schemaVersion을 둔다.

스키마 변경 시 기존 데이터를 무시하거나 덮어쓰지 않고 Migration 경로를 정의한다.

### 2.7 Clock Injection

도메인 로직에서 `Date.now()`를 직접 여러 위치에서 호출하지 않는다.

Clock 인터페이스를 통해 현재 시각을 주입할 수 있게 해서 테스트가 특정 시각을 재현할 수 있게 한다.

### 2.8 Time Zone

기본 시간대는 사용자의 로컬 시간대를 사용한다.

근무 일정은 Local Civil Time 기준으로 정의하고, 실제 이벤트 시각은 절대 timestamp와 timeZone 정보를 함께 보존할 수 있게 설계한다.

### 2.9 Money Precision

기본 입력 금액은 정수 원 단위로 저장한다.

실시간 표시에서 1원 미만 값을 보여줄 수 있으므로 계산 내부에는 충분한 하위 정밀도를 둔다.

V1 권장 기준:

- 저장 급여: integer KRW
- 내부 누적: micro-won 또는 동등 수준 정밀도
- 표시: 설정에 따라 정수 원, 소수 2자리, 고정밀 실시간 표시

부동소수점 tick 누적은 금지한다.

## 3. UX 원칙

- 첫 실행 후 1분 이내에 설정 완료 가능해야 한다.
- 메인 화면에서 현재 상태를 한눈에 이해할 수 있어야 한다.
- 현재 유급인지 무급인지 가장 우선적으로 보여준다.
- 정규 근무가 끝나면 금액 증가는 즉시 멈춘다.
- 정규 근무 후 앱이 계속 근무 상태로 간주하는 동안 기본 문구는 `무료봉사 중`으로 표시할 수 있다.
- 사용자가 `퇴근` 처리하면 무료봉사 카운터도 멈춘다.
- 사용자가 유급 초과근무를 시작하면 무료봉사 상태를 종료하고 추가수당 상태로 전환한다.
- 경고 문구와 상태 문구는 향후 사용자 설정 가능하도록 한다.

## 4. Scope Control

현재 Phase의 문서에 없는 기능은 구현하지 않는 것을 기본으로 한다.

좋은 아이디어라도 다음 Phase 문서에 기록한 뒤 진행한다.

특히 다음은 초기 구현에 섞지 않는다.

- 사용자 계정
- 클라우드 동기화
- 회사별 급여 규정 자동 판정
- 세금 신고 기능
- 실제 근태 시스템 연동
- 금융기관 연동

## 5. 코드 품질 규칙

- TypeScript strict mode
- 급여 및 시간 계산 함수는 UI 프레임워크에 의존하지 않음
- 핵심 계산식은 Unit Test 필수
- 상태 전이는 테스트 케이스 필수
- 저장 Migration 테스트 필수
- 경계 시각 테스트 필수
- Production build 경고 최소화
- 계산 오류를 콘솔 예외로 숨기지 않음

## 6. 완료 기준

기능은 화면이 보인다고 완료된 것이 아니다.

각 Phase는 다음을 모두 만족해야 완료로 본다.

1. 요구사항 구현
2. 핵심 Unit Test 통과
3. 경계 시각 검증
4. 저장 복원 검증
5. 새로고침 검증
6. 모바일 및 데스크톱 기본 레이아웃 검증
7. 문서와 실제 동작 일치
