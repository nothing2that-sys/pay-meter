# PayMeter Open Decisions

이 문서는 아직 최종 확정하지 않은 제품 및 계산 정책을 기록한다.

구현 중 개발자가 임의로 결정하지 않는다.

---

## D1. 급여 배분 방식

현재 권장:

기간 급여를 해당 기간의 예정 유급 정규 근무시간에 배분.

검토할 대안:

- 사용자가 기준 시급 직접 입력
- 고정 월 환산시간 사용
- 법정 환산시간 템플릿

V1 기본은 Period Allocation으로 계획.

---

## D2. 무료봉사 자동 시작 기준

현재 정의:

정규 근무 종료 이후 유급 추가근무가 없고 퇴근 처리 전이면 자동 시작.

검토 포인트:

실제로는 사용자가 이미 퇴근했지만 앱에서 퇴근 버튼을 누르지 않을 수 있다.

후보:

- 매일 자동 무료봉사 시작
- Dashboard가 열려 있을 때만
- 사용자가 `아직 근무 중` 확인
- 정규 종료 후 일정 시간이 지나면 확인 Notification

초기 구현은 자동 시작 + 명시적 퇴근 Action을 기준으로 한다.

---

## D3. 정규근무 조기 퇴근

질문:

사용자가 16:00에 퇴근하면 월급 기반 급여 시각화에서 16:00~18:00 금액을 실제 누적에서 제외할 것인가?

두 가지 의미가 가능하다.

A. 계약 급여 배분 관점
- 월급은 예정대로 받으므로 금액 유지

B. 실제 노동시간 가치 관점
- 근무하지 않았으므로 실시간 Earned에서 제외

V1 Core 구현 전에 제품 의미를 한 번 더 확정하는 것이 좋다.

---

## D4. 유급휴일

월급 근로자의 유급휴일을 어떻게 시각화할지 결정 필요.

후보:

A. 일을 하지 않으므로 실시간 카운터는 증가하지 않지만 월급 총액은 근무일에 재배분

B. 유급휴일 동안에도 계약급여가 실시간 증가

현재 PayMeter 성격에는 A가 더 자연스럽지만 확정 필요.

---

## D5. Overnight Schedule

예:

```
22:00 ~ 07:00
```

초기 V1에서 지원할지 결정 필요.

권장:

MVP에서는 금지하고 이후 교대근무 Phase에서 구현.

---

## D6. 세전과 세후

V1은 입력 금액 자체를 정본으로 사용.

향후:

- Gross
- Net
- 둘 다 표시

세후 자동 추정은 국가별 규칙이 필요하므로 별도 기능으로 분리.

---

## D7. 무료봉사 문구

기본:

```
무료봉사 중
```

향후 선택 가능:

- 정규 근무 종료
- 초과근무 미등록
- 업무시간 초과
- 퇴근하세요
- 사용자 직접 입력

---

## D8. 기간 누적의 의미

Dashboard의 이번 달 금액을 다음 중 무엇으로 볼지 명확히 해야 한다.

- 지금까지 실제 발생한 Pay Segment 합
- 이번 달 계약상 예정 월급 진행률
- 두 값 모두

권장:

두 개념을 분리한다.

```
실제 근무 기준 누적
계약 급여 진행
```

다만 첫 Dashboard에는 실제 근무 기준 누적을 우선한다.

---

## D9. 휴가

연차 사용일의 처리:

- 유급근무처럼 금액 배분
- 실제 노동은 없으므로 별도 Paid Leave State
- 기간 급여에는 포함하되 Work Time에는 포함하지 않음

장기적으로 Paid Leave State를 별도로 두는 방식이 가장 정확하다.

---

## D10. 월급 및 연봉 변경일

급여 변경이 월 중간에 발생할 수 있다.

예:

```
9월 1~14일 4,000,000 기준
9월 15일부터 4,300,000 기준
```

정확한 기간 배분을 위해 Salary Revision을 날짜 기준으로 분리한다.

구현 전 Period Allocation 분모를 Revision 구간별로 계산하는 규칙을 확정해야 한다.

---

## Decision Process

결정이 내려지면:

1. 이 문서에서 상태를 DECIDED로 변경
2. 관련 SSOT 문서에 정식 규칙 반영
3. 테스트 Fixture 추가
4. 구현

Open Decision만 수정하고 구현 Contract에 반영하지 않는 상태는 허용하지 않는다.
